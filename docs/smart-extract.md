# 智能解压 / Smart extraction

在 Windows 资源管理器或 7-Zip 的文件列表中，右击压缩包，选择
**7-Zip → 智能解压至此**。Windows 11 中可能需要先点“显示更多选项”。
可以多选压缩包，每个包分别判断。菜单项可在 **工具 → 选项 → 7-Zip**
的右键菜单列表中启用或停用；升级旧版时默认启用新增菜单项。

## 目录规则

| 压缩包内容 | 解压结果 |
| --- | --- |
| `photos/a.jpg`、`photos/b.jpg` | 直接得到 `photos/`，不再套一层压缩包名 |
| 单个 `a.txt` | `压缩包名/a.txt` |
| 多个散文件 | 全部放入压缩包同名文件夹 |
| 多个顶层文件夹，或文件与文件夹混合 | 全部放入压缩包同名文件夹 |
| `bundle.tar.gz`、`bundle.tar.lz4` 等 | 先解开压缩流，再解 TAR，按 TAR 内容应用以上规则 |

“同一个文件夹”指所有条目共享唯一顶层目录。即使压缩包没有显式存储目录条目，
也能从文件路径识别它。TAR 的 `./` 根目录条目不算第二个目录。

智能模式使用新目录，保留已有内容。若包内的顶层目录已存在（也包括同名文件、
符号链接或目录联接），则改为创建压缩包同名容器，保留内部目录结构。
容器名已存在时使用 `名称 (2)`、`名称 (3)` 等，不覆盖、不合并旧目录。
空 ZIP/TAR 不创建无意义的空容器。

## TAR 与压缩流

支持 gzip、bzip2、xz、LZ4、LZMA、Zstandard 和 Unix compress 流，以及
`.tgz`、`.tbz2`、`.txz` 等常用名称（以对应程序包含的编解码器为准）。
实际解析解码后的内容来判断 TAR；不要求外层文件名带 `.tar`。
如果明确标记为 TAR 的内容无法打开，或外层压缩流截断、校验失败，操作会报错。

不会对普通 ZIP/7z 中包含的压缩文件无限递归解压。例如 ZIP 内的 `backup.tar`
保留为文件。普通的非 TAR 单文件压缩流按单文件规则解压。

双层处理使用自动清理的临时文件，不在目标目录留下中间 `.tar`，不必把整个
TAR 装进内存，但需要容纳解码后 TAR 的临时磁盘空间。普通的“解压到当前文件夹”
等已有命令保持原行为。

## 命令行

```console
7zz x -smart archive.zip
7zz x -smart bundle.tar.gz -ooutput
7z x -smart bundle.tar.lz4 -ooutput
```

`-o` 是放置智能解压结果的父目录；未指定时使用当前工作目录。`-smart-` 可显式
关闭。智能模式只用于 `x` 完整路径解压，不能与标准输入、标准输出、`e`、`t`
或绝对路径解压 `-spf` 合用。筛选规则、密码处理、路径清理及压缩算法仍使用
原生 7-Zip 引擎。

## 参考与差异

参考 [Bandizip 官方“智能解压至此”说明](https://cn.bandisoft.com/bandizip/help/auto_dest/)
中的目录结构判断和容器重名编号。实现为本项目原生 C++ 代码，未使用 Bandizip
程序或代码。按本项目需求，**单个散文件也创建同名文件夹**；Bandizip 官方说明
中的单文件行为是直接解压到当前位置。

上游 93 个语言资源保持原样。新增文字位于 `Lang/Custom/`，提供英文、简中、
繁中和德语；其他界面语言的新菜单项回退到英文。
